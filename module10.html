Key Formulas in Detail

SUMIFS
=SUMIFS(sum_range, criteria_range1, criteria1, [criteria_range2, criteria2, ...])
Sum values where multiple conditions are all met. Example: Total sales in Q1 for Region "North": =SUMIFS(C:C, A:A,"Q1", B:B,"North")
SUMPRODUCT
=SUMPRODUCT(array1, [array2], ...)
Multiplies arrays element-by-element and sums the result. Also acts as array formula without Ctrl+Shift+Enter. Weighted average: =SUMPRODUCT(B2:B10, C2:C10)/SUM(C2:C10)
COUNTIFS
=COUNTIFS(criteria_range1, criteria1, [criteria_range2, criteria2, ...])
Count cells meeting all specified conditions. Segment size: =COUNTIFS(A:A,"Active", B:B,">1000")
TEXT
=TEXT(value, format_text)
Formats a number as text with a specific number format. =TEXT(A2,"DD-MMM-YYYY") converts date serial to readable string. Essential for dashboard labels.
IFERROR
=IFERROR(value, value_if_error)
Returns alternative value if expression results in an error. Cleaner than nested IF: =IFERROR(VLOOKUP(A2,Table1,2,0),"Not Found")

02VLOOKUP vs. INDEX-MATCH

The most common lookup debate in Excel. In interview contexts, understanding the why behind INDEX-MATCH is more important than just knowing the syntax.

VLOOKUP

Excel Formula Syntax
-- Syntax: VLOOKUP(lookup_value, table_array, col_index_num, [range_lookup]) -- Find price of a product by product_id from a lookup table =VLOOKUP(A2, ProductTable, 3, FALSE) -- A2: the product_id to search for -- ProductTable: the range containing your data (product_id must be FIRST column) -- 3: return value from the 3rd column of the table -- FALSE: exact match (always use FALSE for data lookups)
VLOOKUP Limitations

1. Lookup column must be the leftmost column — you can never look up something to the left of the key column.
2. Column index is fragile — if you insert a column in the table, col_index_num 3 now points to the wrong column with no error.
3. No dynamic column reference — the column number is hardcoded, making it brittle for dashboards that change shape.

INDEX-MATCH — The Professional Alternative

Excel Formula Syntax
-- INDEX returns a value from a range given row and column position -- MATCH returns the position of a value within a range -- Combined: look up any value relative to any other column -- Equivalent to the VLOOKUP above: =INDEX(ProductTable[Price], MATCH(A2, ProductTable[ProductID], 0)) -- MATCH finds the row where A2 appears in the ProductID column -- INDEX returns the value from the Price column at that row -- No positional column index — uses named columns directly -- Two-way lookup (row and column both dynamic): =INDEX(DataRange, MATCH(RowKey, RowLabels, 0), MATCH(ColKey, ColHeaders, 0))
CriterionVLOOKUPINDEX-MATCH
Lookup directionLeft-to-right onlyAny direction (left, right, up, down)
Column key stabilityBreaks if columns inserted/deletedRefers to column by name/range; stable
2-way lookupNot possibleYes (MATCH in both INDEX arguments)
Performance (large data)Slightly faster on very small dataFaster on large datasets (matches once)
Modern Excel replacementXLOOKUP (Excel 365)Still the professional standard
When to Use XLOOKUP (Excel 365 / Google Sheets)

=XLOOKUP(A2, ProductTable[ProductID], ProductTable[Price], "Not found")

XLOOKUP combines the simplicity of VLOOKUP with the power of INDEX-MATCH: it searches in any direction, doesn't require a column index number, and has a built-in default value for not-found cases. If you're working in Excel 365 or Google Sheets, XLOOKUP / VLOOKUP-equivalent functions are preferred. For older Excel versions (2016 and below), INDEX-MATCH is the gold standard.

03Pivot Tables

Definition — Pivot Table

A pivot table is an interactive data summarization tool that allows dynamic grouping, filtering, and aggregation of tabular data without writing formulas. It enables analysts to rapidly explore data across multiple dimensions by dragging fields into rows, columns, values, and filter areas.

Pivot Table Anatomy

AreaPurposeExample
Rows Groups data by unique values of the field(s) placed here — one row per unique value Product Category, Region, Month
Columns Creates a cross-tabulation — unique values become column headers Quarter (creates Q1, Q2, Q3, Q4 columns)
Values The numerical field to aggregate; choose function: Sum, Count, Average, Min, Max, % of Total Sum of Revenue, Count of Orders, Average of Rating
Filters Global filter applied before any aggregation — like a WHERE clause Filter by Year = 2024; Country = "India"

Calculated Fields and % of Total

Two of the most important pivot table features for analytics:

  • % of Row Total / % of Column Total / % of Grand Total: Right-click any value cell → "Show Values As" → select percentage type. Instantly converts raw counts to proportions without new columns.
  • Calculated Field: Insert tab → PivotTable → Fields, Items, & Sets → Calculated Field. Define formulas using existing field names. Example: = Revenue / Units to add an "Average Selling Price" column derived from two existing fields.

Slicers and Timelines

Slicers are visual filter buttons that can be linked to multiple pivot tables simultaneously — clicking "North" on a Region slicer filters all connected pivot tables at once. They're the foundation of interactive Excel dashboards. Timelines are slicers specialized for date fields, allowing filtering by year, quarter, month, or day with a visual slider.

Interview Context

Pivot tables are often tested in take-home assignments and Excel-based rounds. Interviewers look for: (1) correct aggregation choice (Sum vs. Count vs. Average), (2) handling of blanks/nulls, (3) meaningful cross-tabulations, and (4) ability to show % breakdowns without additional columns. Knowing that slicers can link multiple pivots shows dashboard design maturity.

04BI Tools — Overview

Business Intelligence (BI) tools allow analysts to connect to databases, build calculated measures, and create interactive dashboards that non-technical stakeholders can use independently. The four most relevant platforms for data analytics roles:

XL

Microsoft Excel

Spreadsheet + Lightweight BI

The universal fallback. Every analytics professional must be proficient. Power Query (for ETL) and Power Pivot (for data modelling) extend it toward BI territory.

  • Available everywhere; no setup
  • Excellent for ad-hoc analysis
  • Power Query for data transformation
  • Familiar to all business stakeholders
PBI

Microsoft Power BI

Enterprise BI Platform

Microsoft's full BI suite. DAX (Data Analysis Expressions) is its formula language for calculated columns and measures. Tight integration with Azure, SQL Server, and Microsoft 365.

  • Strong for Microsoft-stack organizations
  • Cost-effective (included in M365 E3+)
  • Power Query for data transformation
  • DAX for complex business calculations
Tb

Tableau

Visual Analytics Platform

Industry leader for data visualization. Known for its intuitive drag-and-drop interface and powerful visualization capabilities. VizQL (Visual Query Language) drives its chart engine. Salesforce-owned.

  • Best-in-class visualization flexibility
  • Strong for storytelling and exploration
  • Tableau Prep for data wrangling
  • Large analyst community and resources
Lk

Looker (Google)

Semantic Layer BI

Uses LookML, a modelling language that defines metrics, dimensions, and joins at the semantic layer — so every analyst uses the same definition of "revenue" or "active users." Google Cloud-native.

  • Single source of truth via semantic model
  • Excellent for metric governance at scale
  • Git-versioned metric definitions
  • Strong for data teams in GCP environments

DAX Fundamentals (Power BI)

DAX (Data Analysis Expressions) is the formula language for Power BI calculated columns and measures. Understanding its core functions is expected in Power BI-centric roles.

DAX — Common Measure Patterns
-- Basic aggregation measure Total Revenue = SUM(Sales[Revenue]) -- Count distinct customers Unique Customers = DISTINCTCOUNT(Sales[CustomerID]) -- Conditional measure: revenue from new customers only New Customer Revenue = CALCULATE( SUM(Sales[Revenue]), Customers[IsNew] = TRUE ) -- Time intelligence: Year-to-Date revenue Revenue YTD = TOTALYTD(SUM(Sales[Revenue]), Dates[Date]) -- Previous period comparison Revenue PY = CALCULATE( SUM(Sales[Revenue]), SAMEPERIODLASTYEAR(Dates[Date]) ) -- Revenue growth rate Revenue YoY % = DIVIDE( [Total Revenue] - [Revenue PY], [Revenue PY], BLANK() -- Returns BLANK instead of error when PY is 0 )
CALCULATE is the most important DAX function

CALCULATE evaluates an expression in a modified filter context. It's how you apply conditions to measures — similar to adding a WHERE clause to your aggregation. Understanding filter context vs. row context is the key conceptual leap in DAX.

06Dashboard Design Principles

A well-designed dashboard is not just about putting charts on a page — it is about enabling fast, accurate decisions for a specific audience. Poor dashboard design is one of the most common analytics failures.

1
Know Your Audience and Their Decision

An executive dashboard (top-line KPIs, trend vs. target) is very different from an operational dashboard (real-time queue depths, error rates). Define: who will use this, what decision will they make, and how often will they check it? The audience determines metric granularity, chart complexity, and layout.

2
Lead with the Most Important Number

The top-left or top-center of a dashboard is where the eye goes first. Place the primary KPI (revenue, DAU, conversion rate) with clear context: current value, change vs. prior period, and trend direction. Big-number tiles for 3–5 headline metrics, then charts below for detail.

3
Show Context, Not Just Numbers

A number without context is meaningless. Always show: comparison to target or prior period, a trend over time, and the significance of the change. "Revenue: ₹4.2Cr" tells you nothing. "₹4.2Cr — 8% below Q3 2023 target of ₹4.6Cr — declining 3 months in a row" enables a decision.

4
Reduce Cognitive Load

Every element on the dashboard should earn its place. Remove gridlines that don't add information, direct labels beat legends (the eye doesn't have to travel back and forth), consistent color encoding across all charts, and white space is not wasted space — it groups related elements and rests the eye.

5
Use Color Purposefully

Color is a preattentive attribute — it's processed before conscious thought. Rules: one accent color for the primary metric or the "thing to notice"; semantic color for status (green = good, red = bad, yellow = warning); muted neutrals for context; colorblind-safe palette (avoid pure red-green; use blue-orange or add text labels).

6
Design for Scanning, Not Reading

Dashboard users scan — they spend 3–5 seconds before their eye settles on something. Use clear headings, consistent visual hierarchy, and grouping that chunks related metrics. Critical information should not be buried below the fold or hidden behind a filter. If you have to explain how to read the dashboard, it needs a redesign.

7
Filter and Interactivity with Defaults

Filters are powerful but must have sensible defaults — a dashboard that opens blank because no filter is selected is a failure. Pre-select the most common view (current month, all regions) and let users drill down. Limit the number of filters visible at once to avoid decision paralysis.

07Interview Q&A

When would you use INDEX-MATCH instead of VLOOKUP? Explain with an example.

INDEX-MATCH should be preferred over VLOOKUP in three situations:

1. Lookup to the left of the key column. VLOOKUP only looks rightward. If your product ID is in column D and the product name you want is in column B, VLOOKUP cannot retrieve it. INDEX-MATCH can: =INDEX(B:B, MATCH(H2, D:D, 0)) — find the row where H2 appears in column D, then return the value from column B at that row. No restriction on relative column positions.

2. Fragile column index numbers. =VLOOKUP(A2, Table, 4, FALSE) returns column 4. If someone inserts a column into the table, column 4 now contains different data and the formula returns wrong results silently. INDEX-MATCH uses named ranges or explicit column references that don't shift with insertions.

3. Two-way lookups. To find a value at the intersection of a specific row label and column header: =INDEX(DataRange, MATCH(RowKey, RowLabels, 0), MATCH(ColKey, ColHeaders, 0)). VLOOKUP cannot do this without helper formulas.

If working in Excel 365 or Google Sheets, XLOOKUP supersedes both — it handles leftward lookups, has a built-in error default, and doesn't require an exact positional column number.

What is the difference between Power BI's DirectQuery and Import mode?

This is a fundamental architectural choice in Power BI that affects performance, data freshness, and scale.

Import mode: Power BI fetches all the data from the source, compresses it, and stores a copy inside the Power BI file (.pbix) / Power BI Service. Queries are run against this in-memory copy using Power BI's VertiPaq engine. Extremely fast for report users (queries take milliseconds); but (1) data is a snapshot — you must refresh (manually or scheduled) to get new data, and (2) dataset size is limited (~10 GB in Power BI Service on standard capacity).

DirectQuery mode: Power BI generates and sends SQL queries to your source database in real-time, every time a user interacts with the report. The database processes the query and returns results. Advantages: always shows current data with no refresh lag; can query arbitrarily large tables. Disadvantages: performance is limited by your database query speed; not all DAX functions work; heavy user traffic can overload the database.

When to use which: Use Import for most reporting scenarios where data updates daily/hourly and table sizes are manageable. Use DirectQuery for operational dashboards requiring real-time data, or when tables exceed the size limit. A Composite Model (mixing both modes in one dataset) is the modern hybrid approach — import frequently-used lookup tables for speed, DirectQuery large fact tables for freshness.

What makes a good dashboard? How would you design a dashboard for a Head of Sales?

A good dashboard enables fast, accurate decisions for its specific audience with minimal cognitive effort. The three principles are: (1) audience-first design — know their question before choosing metrics; (2) show context — numbers alone are meaningless without comparison to target, prior period, or benchmark; (3) reduce noise — every element either earns its place by informing a decision, or it gets removed.

For a Head of Sales:

Step 1 — Understand their question. A Head of Sales asks: "Are we on track to hit quota? Where are we behind? Which reps or regions need attention?"

Step 2 — Headline KPIs (top of dashboard):

  • Revenue: Month-to-date vs. monthly target (with % attainment)
  • Deals Closed: current month count vs. target
  • Pipeline Value: total qualified pipeline vs. 3× coverage goal
  • Average Deal Size vs. prior quarter

Step 3 — Supporting charts:

  • Revenue trend: daily/weekly MTD vs. same period last month
  • Rep performance: horizontal bar chart — each rep, sorted by % attainment; color-coded red/yellow/green by attainment threshold
  • Pipeline funnel: deals by stage with win rate by stage
  • Region map: if multi-geography, heatmap by revenue attainment

Step 4 — Filters: Default to current month; allow drill-down by rep, region, product line. Keep to 3 filters maximum — more creates decision paralysis.

Step 5 — Design choices: Accent color (blue) on the primary revenue KPI; red/green semantic color only for attainment status; data refreshes daily at 7 AM with a visible timestamp; one page for the executive summary, a second page for rep-level drill-down.
